# Relay security audit — 30 September 2026

The audit found seven application defects and repaired them: four authorization races and three Nearby weaknesses. It also hardened the runtime image and pinned the CI actions. This report records the running-copy tests, source reviews, independent verification, and remaining limits. It supersedes the 27 September report; those earlier fixes remain in the baseline.

**Completed and deployed.** The verified application source is `427ac58f32fb1b90be4320ec582b5b141779d7b0`; the tested and live image is `sha256:c4a1f4a2bb04db5cbf9bf2f10f4ce664e71b259dbf9f5d00800c9cb0aaf3eaaa`. Relay was updated at 10:39 UTC on 30 September 2026, preserving its data and deployment configuration. The source changes are integrated into the original checkout. No remote push was performed.

## What was audited

The source baseline was `76044ebd57fd92b037ddc11defe4fe2d1331eb87`. Work ran in an isolated `codex/security-audit` checkout so the original files and real data were preserved. Attack fixtures used disposable accounts, directories, databases, ports and containers. Reviews covered all 88 contract endpoints and 136 registered HTTP operations, including automatic HEAD, event streams, public content and tus upload routes. Browser-side Nearby, the Unix-socket/UDP Direct helper, static hosting, container configuration, dependency lockfile and all 15 locally available Git commits were included.

The attacker roles were anonymous Internet callers, forged sessions, members accessing another member’s resources, share/code holders, upload-request guests, Nearby guests, people on the same network, cross-site browsers and untrusted/rebound hosts. Administrators were tested against API ownership boundaries but remain trusted administrators: they can intentionally reset a member’s password and thereby impersonate them. Uploaded active content and malformed image/transfer inputs were also exercised.

The live service uses `https://relay.walriyami.com`, a Cloudflare tunnel and an explicitly trusted `cloudflared` connector. Its HTTP port is bound to loopback. Live checks were read-only; destructive or authenticated attack tests ran on disposable instances.

## Attacks that failed

These are concrete checks, not conclusions drawn only from successful feature tests:

- Anonymous, forged-session, share-holder, request-guest, Nearby-guest and same-network-stranger calls to protected member/admin operations returned 401/403. Ordinary members received 403 from administrator routes.
- Unsafe requests from a foreign Origin or `Sec-Fetch-Site: cross-site`, authenticated changes missing CSRF, and requests with an untrusted Host returned 403. Health GET/HEAD is deliberately exempt from Host validation and exposes no user or file data.
- A different member could not read or mutate another member’s items, nodes, transfers, links, request submissions or deliveries by changing IDs. Deduplicated identical blobs retained independent ownership. An administrator could not directly browse another member’s private item/content/thumbnail/ZIP/submission/visit APIs or bypass a share password.
- A share token did not authorize nodes outside its share. Password, recipient, expiry and revocation gates applied to metadata, content, thumbnails, ZIP, ranges and conditional representations. Revoked/expired links were denied before maintenance ran.
- Request-guest cookies could not authorize another request or owner. Simultaneous guests could not oversubscribe the request’s byte reservation; member and guest uploads both obeyed the owner’s storage quota.
- Device/invitation capabilities were single-use and ownership/session-bound. Suspension, reset, password changes and expiry revoked dependent sessions/codes/streams. Existing software-authenticator tests used real WebAuthn verification.
- Browser-forged Direct identity headers failed. Real Unix-socket calls required the helper MAC/session, refused nonbulk route/method confusion, and lost authority after signout/expiry/reset/suspension. Socket/directory modes were 0600/0700.
- Same network visibility did not let unauthenticated strangers become members. Nearby guests were scoped to their host; foreign members could not remove them or signal across network/visibility boundaries. Removing guests ended their event stream and future signaling.
- Traversal/ambiguous filenames, malformed tus offsets, oversized inputs and upload races did not overwrite committed storage. Oversized image dimensions were refused before allocation.
- Uploaded HTML/SVG was served as inert plain text or attachments with sandbox/no-sniff protection. Static hosting did not expose env files, source, databases or private data.

See [the full operation/actor table](security-audit/endpoint-roles.csv) and [machine-readable route evidence](security-audit/route-matrix.json). All 136 operations and 2,040 actor cells are accounted for. Specific, source-attributed security assertions cover 114 operations. The other 22 lack an extra curated security scenario: 20 HEAD variants, the member’s own passkey inventory and tus OPTIONS; they retain their recorded hook/control evidence. There are 1,012 not-checked cells, including deliberately inapplicable actor combinations. A boundary rejection at a placeholder ID proves the early gate, not resource ownership correctness. Detailed valid-resource assertions are separately identified. Feature/setup request observations are not labeled attacks. Untested cells remain visible.

## Supply chain and runtime

CI’s twelve action references were changed from mutable tags to verified full commit SHAs. The Docker base is pinned to `node:24-bookworm-slim@sha256:0e0ff40c39bc087845bfb27465a0df4ea419520094bc35842ff83dd8cbe6f9b6`. The runtime applies available Debian updates and removes unused npm/Yarn. Docker update checks now run weekly.

The deployed baseline image had 19 bundled npm advisory entries and 9 Debian advisory entries with available fixes. The final image has **zero Node/npm advisories and zero Debian entries with an available vendor fix** at the scan time. It still has **229 Debian advisory entries representing 104 unique CVEs**, including 52 High and 4 Critical entries. No reachable Relay exploit was demonstrated for those entries; their presence is not dismissed as harmless. The Critical entries name three Perl issues and zlib’s `CVE-2023-45853`. Relay does not invoke Perl or shell commands for uploaded files; native library/decoder internals remain a separate residual risk.

`npm audit` found zero lockfile advisories for both all and production dependencies. Gitleaks initially scanned all 15 available commits; its two findings were confirmed synthetic verification/test secrets. The final history scan streamed all 16 available commits’ patches (4.85 MB) into offline Gitleaks, then mapped the five redacted occurrences back to source. All five are repeated appearances of those same two synthetic fixture values in `tests/support/config.ts` and the historical `LOCAL_SECRET` in `scripts/lib/relay.ts`; no new credential was found. A Docker worktree scan that reported zero commits was rejected as invalid evidence. Final Semgrep ran 270 rules over 1,521 targets and found only three optional Dependabot cooldown recommendations; automatic seven-day delays were not added. Its partial parser warning for `export type *` in `client/api.ts` was reviewed manually. Baseline CodeQL’s security-extended job genuinely ran init/analyze successfully; the final local candidate has not been independently run through hosted CodeQL.

## Assumptions and remaining limits

- No finite audit proves that every possible program path is secure. The table accounts for every registered operation, with explicit tested/read-only/not-checked distinctions; arbitrary input combinations, time schedules and future changes are not exhaustively covered.
- Admin, host, data-volume and backup access is trusted. Files are not end-to-end encrypted. This audit does not remove the administrator’s intentional reset powers.
- Four-/six-digit pickup and device codes deliberately trade security for convenience. Existing persistent lockouts/global pause/rotation are tested, but a lucky early guess is possible and can reveal a durable bearer URL. Sensitive shares should use passwords and appropriate recipients/lifetimes; rotate/revoke learned bearer URLs separately.
- Native image/PDF/HEIC decoding and WebRTC libraries were not exhaustively fuzzed. Worker threads are not an operating-system decoder sandbox. Container controls do not guarantee safety against native-code/kernel flaws or all denial of service.
- Nearby revocation reaches an established peer when the authoritative directory update arrives. It cannot retract files already received or force a remote hostile device to erase its copy.
- External Cloudflare configuration, the whole host/network, unavailable Git history and unrelated services were outside source control. Scripted public clients met Cloudflare 1010; ordinary Chromium reached Relay and confirmed health, completed setup, anonymous denials, invalid-link refusal, and security headers. Live checks did not use real-user credentials or mutate their files.
- This is an AI-assisted source and running-copy audit, with separate 6.1 Sol producer/verifier contexts for the auth/transfer and Nearby findings. It is not a professional penetration-test certification; original broad worker sessions were interrupted before their full narrative reports, so their saved assertions were supplemented by fresh independent reviewers and the coordinator’s inventory/scans/tests.
